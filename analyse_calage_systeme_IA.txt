## 1. Ce qu'est le calage systeme

Le calage suit une sequence stricte ou chaque etape depend de la precedente :

| Etape | Action | Parametres DSP |
|-------|--------|---------------|
| 0. Verification | Polarite, gain staging, signal flow | Mute |
| 1. Positionnement physique | Aim, splay, placement subs | Aucun (mecanique) |
| 2. Niveaux | Equilibre entre sous-systemes | Gain (0.1-0.5 dB) |
| 3. Delay | Alignement temporel sub/main, fills, delays | Delay (0.01 ms) |
| 4. Crossover | Alignement de phase a la frequence de coupure | Filtre HP/LP, pente, all-pass, polarite |
| 5. EQ | Correction de la reponse en frequence | PEQ (freq, gain, Q) |
| 6. Verification | Walk-through, mesures multi-positions | - |

Point cle (Bob McCarthy) : l'objectif n'est pas de "faire sonner bien" mais de "faire sonner pareil" partout. Le calage vise la coherence spatiale, pas le rendu artistique.

## 3. Ce qui n'existe PAS encore

Personne n'a construit de boucle fermee automatisee pour le calage PA pro :

  Mesure -> Analyse -> Decision -> Application DSP -> Re-mesure -> Verification

- Les outils pro (Smaart, SysTune) mesurent mais ne corrigent pas
- Les outils qui corrigent (TRACT, Dirac) ne controlent pas de DSP externe
- Les ecosystemes constructeurs (L-Acoustics, d&b) sont fermes a leur materiel
- Les projets open source ciblent le home cinema, pas le PA

C'est exactement le trou dans le marche que le projet viserait.

                      └────────────────┘   └─────────────────┘

### Le goulot d'etranglement : le DSP

Le t.racks DSP 206 est le maillon faible. Options :

1. Reverse-engineer le protocole USB HID — Faisable avec Wireshark + USBPcap en capturant les trames du Processor Editor. Risque : fragile, non documente, peut casser avec une mise a jour firmware.

2. Remplacer par un DSP avec API :
   - CamillaDSP (gratuit, API WebSocket, Linux/Windows) — ideal pour un prototype
   - miniDSP (certains modeles ont une API plugin)
   - QSC Q-SYS (Lua scripting, API reseau) — overkill mais tres puissant
   - Biamp Tesira (API de controle reseau)

3. Smaart Data Modeler peut exporter vers QSC Q-SYS, Powersoft, Biamp, Linea Research, Symetrix — une passerelle possible.

## 5. Limites fondamentales

### Ce que l'IA peut faire
- Calculer les delays optimaux depuis les IR
- Generer un EQ correctif par Match Target
- Optimiser des filtres sur plusieurs positions de mesure (optimisation multi-objectif)
- Detecter la polarite
- Matcher les niveaux entre sous-systemes

### Ce que l'IA ne peut PAS faire
- Choisir ou placer le micro de mesure — ca determine tout le reste
- Interpreter la coherence — distinguer "donnee fiable montrant un vrai probleme acoustique" de "donnee pourrie a ignorer" demande de l'experience
- Decider quoi corriger vs quoi accepter — un creux de 10 dB a 2 kHz cause par une interference physique ne peut pas etre corrige par EQ sans degrader les autres positions
- Gerer les compromis multi-zones — optimiser le parterre degrade le balcon, et vice versa
- Adapter en temps reel pendant le show — changement de temperature, arrivee du public, choix artistiques du mixeur
- Repositionner physiquement les enceintes — aucun DSP ne compense un mauvais aiming

### Risques du projet
- L'EQ automatique sans supervision est dangereux : booster un creux d'interference gaspille du headroom et peut endommager les transducteurs
- Le calage sub est le plus complexe : Bob McCarthy lui-meme dit qu'il n'utilise pas l'IR pour le calage sub, il utilise la trace de phase de la fonction de transfert
- Les parametres interagissent : changer l'EQ modifie la phase, ce qui peut defaire l'alignement de delay precedemment regle

## 6. Verdict : est-ce realiste ?

Oui, mais par etapes :

| Phase | Objectif | Difficulte |
|-------|----------|-----------|
| v0.1 | Script qui lit les mesures REW, calcule les delays, suggere un EQ correctif | Facile |
| v0.2 | Boucle fermee avec CamillaDSP : mesure -> calcul -> application -> re-mesure | Moyen |
| v0.3 | Multi-positions : optimisation EQ qui minimise la variance sur N points de mesure | Moyen-difficile |
| v0.4 | Integration DSP reel (reverse-eng t.racks ou migration vers DSP avec API) | Difficile |
| v0.5 | IA qui apprend les patterns de calage et propose des strategies | Ambitieux |

Recommandation : commencer avec REW Pro + CamillaDSP (tous deux ont des API). Laisser tomber le t.racks DSP 206 pour le prototype — son absence d'API est un frein majeur. Une fois la boucle fermee fonctionnelle avec CamillaDSP, migrer vers n'importe quel DSP avec API.

## 2. Pourquoi l'IA peut suivre la trace de phase

Le calage c'est :

  1. Mesurer la phase des 2 sources (sub + top par ex.)
  2. Observer le decalage de phase dans la zone de crossover
  3. Essayer un delay -> re-mesurer -> pas bon
  4. Essayer un autre delay -> re-mesurer -> mieux mais pas parfait
  5. Essayer d'inverser la polarite -> re-mesurer
  6. Ajouter un all-pass -> re-mesurer
  7. Recommencer jusqu'a ce que les traces de phase soient alignees (<60 deg)

C'est exactement une boucle d'optimisation que l'IA fait mieux et plus vite qu'un humain.

### Ce que l'IA peut calculer directement

- Delay optimal : la pente de la trace de phase est directement proportionnelle au delay.
  L'IA peut calculer le delay exact : delay = -dphi/df / 360°

- Polarite : si les phases sont decalees de ~180° dans la zone de crossover -> inverser

- All-pass filter : si apres delay + polarite il reste un offset de phase, un filtre all-pass
  a la bonne frequence/Q peut corriger. C'est un calcul mathematique.

- EQ correctif : une fois la phase alignee, la correction frequentielle est un probleme
  d'optimisation classique (minimiser l'erreur entre la reponse mesuree et la cible)

### L'avantage de l'IA sur l'humain

|                    | Humain                          | IA                                              |
|--------------------|---------------------------------|-------------------------------------------------|
| Mesure->ajustement | 5-15 min par iteration          | < 1 seconde par calcul                          |
| Nb d'iterations    | 3-10 (fatigue, impatience)      | Illimite                                        |
| Precision delay    | 0.1 ms (au feeling)             | 0.001 ms (calcul exact)                         |
| Multi-variable     | Ajuste 1 param a la fois        | Peut optimiser delay+polarite+all-pass ensemble |
| Multi-position     | Trop long -> 1-2 positions      | Peut optimiser sur N positions                  |

## 4. Architecture realiste du projet

  ┌──────────────┐                    ┌──────────────────┐
  │   REW Pro     │<── REST API ────>│   Script Python   │
  │  (mesure)     │   localhost:4735  │   (cerveau IA)    │
  └──────────────┘                    └────────┬─────────┘
                                               │
          Boucle automatique :                 │
          1. Mesurer (REW)                     │
          2. Lire trace de phase (API REW)     │
          3. Calculer delay/polarite/all-pass  │
          4. Appliquer sur DSP (API OSC/WS)    │
          5. Re-mesurer -> verifier            │
          6. Iterer jusqu'a convergence        │
                                               │
                                      ┌────────▼─────────┐
                                      │   DSP externe     │
                                      │  Behringer XR18   │
                                      │  (OSC UDP)        │
                                      │  ou CamillaDSP    │
                                      │  (WebSocket)      │
                                      └──────────────────┘

### Stack technique

- Python comme langage principal
- REW API (requests HTTP) pour la mesure et l'analyse
- python-osc pour controler le Behringer XR18
- ou pyCamillaDSP pour controler CamillaDSP
- NumPy/SciPy pour le traitement de signal (calcul de pente de phase, optimisation de filtres)
- Optionnellement un LLM pour interpreter les resultats et generer des rapports comprehensibles

### Workflow automatise

  Phase 1 : DELAY
    -> Mesurer sub seul, mesurer top seul
    -> Extraire les traces de phase via API REW
    -> Calculer le delay optimal (pente de phase)
    -> Appliquer sur le DSP
    -> Re-mesurer les deux ensemble -> verifier la sommation

  Phase 2 : POLARITE + ALL-PASS
    -> Si phase decalee >120° dans le crossover -> inverser
    -> Si offset residuel -> calculer all-pass (freq, Q)
    -> Appliquer -> re-mesurer

  Phase 3 : EQ
    -> Mesurer la reponse combinee
    -> Comparer a la courbe cible (flat, house curve, etc.)
    -> Calculer les filtres PEQ correctifs
    -> Appliquer -> re-mesurer -> iterer
